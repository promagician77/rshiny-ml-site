# Churn scoring in R: demo page

Static page for the `churnscore` build. No build step: `index.html`, `style.css`, `js/`, `data/`, `img/`, `fonts/`.
Deploy with Vercel (`vercel.json` sets `X-Robots-Tag: noindex, nofollow`). Prepared by Santiago.

The page is generated by `tools/build_site.py` from the measurement files; `data/model.json` is the production glmnet model exported from R for the in-browser scorer.

## Not measured

- The data is IBM's public telco churn sample (from the `modeldata` R package), not a client's. Drifted batches are hold-out customers filtered or adjusted to imitate a campaign, a price rise and a fibre push.
- Batches of 10,000 to 1,000,000 rows resample hold-out customers, so they test speed and memory, not accuracy.
- Concurrency was tested with two users on one process. No load test with many users, and no multi-process deployment behind a load balancer.
- API latency was measured on the same machine, with no network in the path.
- R packages came from Ubuntu's archive (CRAN was unreachable from the sandbox), so versions are older than current CRAN. The bundle records them and `load_bundle()` warns on a mismatch. Debian's DT package lacks one Bootstrap 5 stylesheet, so the app uses DT's default style.
- `deploy/Dockerfile` was not built or run: the sandbox has no container registry access.
- The validation faults come from a generator I wrote, so the result shows each rule works, not that every kind of bad data is caught.
- Hardware: a 2-core sandbox. Timings will differ on other machines.
